> 建立于 2026-09-23。用途:补齐 MMBoard(会议纪要生成系统)从需求到移交的完整研发流程文档。
> 文档定位:as-built(按实际建成状态整理)——系统已上线运行并通过最终验收,文档如实记录现状,不描绘规划态。

## 1. 项目一句话

MMBoard 是部署于内网的会议纪要生成系统:上传会议录音/录像 → 抽取音轨 → 转写(讯飞云 lfasr 或本地 FunASR)→ LLM 分析(OpenAI 兼容 / Anthropic 协议,超长会议自动分块)→ 渲染 ALE 规范 HTML 纪要。React SPA + Node/Express 单实例,单管理员,Docker 部署。

## 3. 写作与维护约定

1. **命名**:文件名沿用 `MMBOARD_<主题>.md`,与仓库根目录的复审/验收档案(MMBOARD_*REVIEW/ASSESSMENT*.md)区分:根目录是历史审计档案,`docs/` 是活文档。
2. **口径**:版本口径、验收边界、迭代划分以《验收报告》和《关键决策记录》为准,各文档引用而不复制。
3. **事实来源**:接口与字段以 `server/server.cjs`、`src/lib/*.ts` 为准;部署以 `deploy/deploy.cjs` 为准;测试以 `scripts/` 为准。文档与代码冲突时,先改文档再改代码或反之,**不允许长期不一致**。
4. **敏感信息**:文档中禁止出现真实密钥/密码;生产主机与内网地址允许出现(内网部署约定)。凭据类信息一律指向《配置与密钥管理》。
5. **变更**:每次发布后,涉及文档在变更说明中列出;`docs/README.md` 的状态表随更新维护。

## 4. 外部自动索引(DeepWiki)的定位说明

GitHub 上的 [DeepWiki/apllozhang/MMBoard](https://deepwiki.com/apllozhang/MMBoard) 是第三方服务按仓库代码自动生成的代码导航(27 个子页,带源码行号锚点,锚定提交随其重新索引浮动)。

**定位与使用口径**:
- ✅ 可用作**代码阅读导航**:新人按其目录(任务管道/LLM 层/持久化/前端等)快速定位文件;
- ❌ **不作为验收、运维或移交的依据口径**:抽查发现其覆盖有缺口(如 SSRF 专页未覆盖 `guardedFetch` 逐跳校验与设置测试接口复用——恰为 R05 验收核心),且存在行号锚点随代码演进失效、索引滞后于最新提交的固有问题;
- 本 `docs/` 文档库为唯一权威口径;两者冲突时以 `docs/` 与代码实现为准。
