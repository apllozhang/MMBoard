## 一、本轮必须修正的文档缺陷

### P1-1：发布流程图的切换顺序与代码相反

**位置：**`docs/diagrams/06-发布与回滚流程.drawio`，以及由它导出的同名 SVG。

图中标为“切换后核验、`DEPLOY_DRILL=1` 在此注入”的节点，当前位于“停旧容器 → 起生产容器”之前；该节点的失败分支还直接连到回滚。读者按图理解，会以为演练在切换前注入并回滚。`deploy/deploy.cjs` 的实际顺序是：候选健康检查通过 → 记录旧镜像 ID → 停旧起新 → 正式容器版本核验；`DEPLOY_DRILL=1` 只在最后的版本核验处设置不匹配的期望值。

**修改要求：**

1. 将“候选健康检查”和“切换后正式容器版本核验”画成两个不同节点。
2. 正确连线：候选检查失败 → 清理候选、旧容器继续运行；候选检查通过 → 停旧起新；正式容器核验失败 → 用旧镜像 ID 回滚。
3. 把 `DEPLOY_DRILL=1` 注入点标在**切换后的正式容器版本核验**节点，并注明生产可能短暂运行新版本。
4. 先修改 `.drawio` 源，再重导 SVG；逐项检查 SVG 可见文字、节点顺序与连线。

**复核通过的证据：**图源、SVG、《部署手册》§2/§5 与 `deploy/deploy.cjs` 对同一流程给出相同顺序；从任一失败分支都能判断是否已经切换生产容器。

### P1-2：`analysis.json` 示例包含未落盘字段

**位置：**`docs/02-设计/MMBOARD_数据设计说明.md` §6.2。

该节已正确展示 `analysis.json` 的顶层 `{analysis, talkStats, meta}`，但示例在落盘的 `meta` 中列出 `generatedAt` 和 `meetingOccurredAt`。`server/pipeline.cjs` 的 `analyzeAndRender` 只把这两个字段传给当次 HTML 渲染，并未把它们写进 `analysis.json`。

**修改要求：**

1. 从 `analysis.json` 的持久化示例 `meta` 中移除这两个字段。
2. 在示例旁说明：**渲染时传入的元信息**与**持久化到 `analysis.json` 的元信息**不是同一字段集合。
3. 以 `writeJsonAtomic(path.join(outDir, "analysis.json"), …)` 的实参为准，逐字段复核示例；如字段为可选、推导或仅渲染时存在，应明确标注。

**复核通过的证据：**示例的每个顶层和嵌套键都能在实际写入对象中找到，读者按示例编写读取程序不会依赖不存在的字段。

### P2-1：总索引给出不存在的替代入口

**位置：**`docs/README.md` 的阅读路径说明、写作与维护约定、快速入口表。

阅读路径说明要求读者使用“替代成文文档”列，但快速入口表没有这一列；同时，写作约定仍将骨架状态的《关键决策记录》列为版本和边界依据。这与“骨架尚不可作为操作依据”的规则冲突。

**修改要求：**

1. 为每个被快速入口引用的骨架提供**具体、已成文**的替代文档或历史裁定章节；也可以直接将快速入口改为只指向已成文资料。
2. 调整写作约定：当前版本与验收边界应以已成文的《验收报告》和具体裁定档案为准；《关键决策记录》填实并核对后再成为正式入口。
3. 从“新接手维护者”“部署升级”“测试验收”“项目管理审计”四条路径各走一次，确认不会在关键操作或判断处停在骨架文档。

**复核通过的证据：**索引所称的列实际存在，或相关说明已删除；每条阅读路径都能到达可使用的成文依据。

## 二、达到教程级质量的执行标准

本轮复核解决的是**事实正确性**。要达到可供同行认可的教程级水平，还需要让不熟悉项目的读者独立完成任务，并留下可检查的证据。

### 1. 每个关键操作都能执行和验证

部署、回滚、备份恢复、凭据轮换、故障处理等章节统一包含：

| 要素 | 应写明的问题 |
|---|---|
| 前提 | 在什么环境、持什么权限、服务应处于什么状态？ |
| 操作 | 在哪台机器、哪个目录执行什么步骤？参数怎样取得？ |
| 预期 | 成功会出现什么响应、日志或文件？ |
| 核验 | 用什么独立检查确认结果，而非只相信命令退出码？ |
| 失败处理 | 失败后从哪里诊断、何时停止、怎样恢复？ |
| 影响 | 是否切换生产服务、修改数据，是否存在短暂不可用？ |

命令中的占位符必须有查询或填写方法。对生产有影响的演练须明确授权窗口、影响时长的估计依据、回滚依据和演练后检查点。

### 2. 示例可由实现直接核对

接口响应、JSON 文件、命令输出和错误信息的示例须标明是“真实采样后脱敏”还是“按代码构造的示意”。示意值可以替换，但**字段层级、类型、单位和可选性不能虚构**。每个持久化示例应指出读写代码位置；每个接口示例应指出路由及前端调用位置。

### 3. 图、正文、索引保持同一事实

流程图不仅要包含正确文字，**箭头顺序和失败分支**也必须正确。每次修改图示，检查 `.drawio` 源、导出 SVG、正文图注和 `diagrams/README.md` 引用登记。总索引需准确反映文档状态，骨架不能被当作执行或裁定的终点。

### 4. 变更后仍能维护

每篇成文文档保留适用功能版本、最近核对日期、维护责任人和事实依据。维护责任人从“待指定”变为实际角色或姓名后，应在索引与文档头同步更新。功能变更时从代码改动反查文档、示例和图，避免只更新其中一处。
