# MMBoard 应急预案与故障处理

| 项 | 值 |
|---|---|
| 版本 | v1.0(as-built) |
| 日期 | 2026-09-23 |
| 基线 | `7e55f94` |
| 关联 | 《运维手册》《详细设计说明书》§5/§6 |

> 总原则:系统的设计取向是 **fail-closed + 如实呈现**——损坏/故障时明确失败并给人工指引,绝不静默降级或伪装成功。应急处理的第一步永远是看任务详情步骤 note 与容器日志里的原话。

## 1. 快速定位路径

```
现象 → 看板任务详情(steps[].status/note) → docker logs 关键字
  涉及转写额度 → data/quota.json 与 .bak
  涉及任务编号/创建 → data/seq-highwater.json
  涉及设置丢失/接口 500 → data/settings.json 与 .bak、[persist] 日志
  涉及发布 → /api/version 的 commit + 部署日志
```

## 2. 额度记账文件损坏(quota.json)

**表现**:新任务在上传后很快失败,错误含「额度记账文件损坏/不可写…请人工修复」;或任务完成但看板有「额度未记账」徽标。

**设计语义**:双坏(quota.json 与 .bak 都解析失败)时,系统在**付费转写发起前**拒绝任务(不消耗额度);转写成功后记账失败则显式标记任务,不影响纪要交付。

**恢复步骤**:
1. 查看 `data/quota.json` 与 `quota.json.bak`:哪份可解析;
2. 可解析的那份手工复制覆盖另一份;两份皆坏时,按备份恢复,或手工重建 `{"YYYY-MM-DD": 秒}`(当日秒数可参考讯飞控制台用量,**宁少勿多**——少记影响仅是余量提示保守);
3. 删除 `.corrupt` 隔离文件(可选,供分析后清理);
4. 重新上传失败的任务验证;
5. 有「额度未记账」徽标的历史任务:按讯飞控制台实际用量把秒数补进当日键,补记后徽标不会自动消失(属历史事实),在任务备注/移交记录中注明即可。

## 3. 任务卡住(queued 或某阶段长时间不动)

| 阶段 | 常见原因 | 处置 |
|---|---|---|
| queued | 前序任务在跑(串行队列)或已堆积 | 等待;堆积过多可删除部分排队任务 |
| extracting | ffmpeg 进程异常 | 日志看 ffmpeg 报错;删除任务重传 |
| transcribing(讯飞) | 轮询重试中(退避最长 60s/次)或外部故障 | 看 `[llm]`/讯飞日志;讯飞控制台查任务状态;确认外部故障→等恢复后"重跑";额度/签名类失败会明确报错 |
| transcribing(本地) | FunASR 工作机离线/排队 | `curl http://10.10.10.144:8300/health`;恢复后任务若已失败则重跑;工作机自身 TTL 会清理残留 |
| analyzing | LLM 挂起(空闲超时 20 分钟会中断并重试一次) | 超过 ~45 分钟无进展判定为异常:确认 LLM 服务,删除任务重传 |
| rendering | 极少见 | 日志 + 删除重传 |

**禁止**:直接改 tasks.json 手工改状态(会破坏 runId 一致性);应删除任务重传。

## 4. 状态文件损坏(settings/auth/seq-highwater/tasks)

系统自愈顺序:主文件坏 → 自动用 `.bak` 恢复(日志 `[persist] … 已用 .bak 恢复`,损坏副本存 `.corrupt`);主备双坏 → 相关操作 **fail-closed**:

| 文件 | 双坏表现 | 人工恢复 |
|---|---|---|
| seq-highwater.json | 拒绝创建新任务(错误含人工指引) | 从备份恢复;或按现存任务+outputs 目录最大编号手工重建 `{"YYYYMMDD": N}`(**宁大勿小**,防编号复用) |
| settings.json | 报「设置数据不可读」 | 从备份恢复;或删除两文件后重启(回到未配置状态,重新在设置页配置) |
| auth.json | 认证不可用 | 从备份恢复;或删除后重启(重新初始化一次性口令) |
| tasks.json | 看板不可读 | **从备份恢复**(任务数据无重建手段;凸显备份纪律) |

恢复后删除 `.corrupt` 前先留档分析。

## 5. 外部服务故障

| 故障 | 表现 | 处置 |
|---|---|---|
| 讯飞不可用/签名失败 | 任务 transcribe 步明确失败(HTTP/业务码) | 控制台核对密钥与套餐;恢复后重跑;密钥轮换见《配置与密钥管理》§6 |
| 讯飞额度耗尽 | 任务失败,额度提示 | 切换本地 FunASR 通道(设置页,对新任务生效)或等次日额度 |
| LLM 超时/空正文/5xx | analyze 失败,自动重试一次后仍失败则任务 failed | 确认模型服务;重跑(仅分析)即可,不重转写 |
| LLM 返回被截断/缺字段 | 任务 done 但纪要有 partial 横幅 | 纪要可用但标注不完整;建议重跑分析 |
| 分块提取部分失败 | 纪要顶部「第 N 块提取失败,纪要可能缺失」横幅 | 纪要谨慎使用;重跑分析;持续出现则查 LLM 服务稳定性 |
| 本地 FunASR 离线 | 任务 transcribe 明确失败;主服务不受影响 | 恢复工作机后重跑;或临时切回讯飞通道 |
| 行动项证据警示 | 纪要行动项带黄色警示 | 属正常校验结果:核对原文/时间;重跑分析通常改善 |

## 6. 发布失败/异常版本

- deploy.cjs 自动回滚:候选验证或切换失败 → 自动用旧镜像重启;
- 若已切换后发现业务异常:按《部署手册》§4 手动回滚到上一镜像 ID(台账可查);
- 回滚后核对 `/api/version` 与看板任务列表;数据卷不动。

## 7. 安全类事件

- 疑似密钥泄漏:按《配置与密钥管理》§7 应急流程;
- 异常登录:审计日志定位;改密并检查令牌撤销(重启服务可强制全员下线);
- 误删任务:无恢复手段(删除即清理),从备份恢复该时点数据卷(评估是否值得)。
