## 2. 运行环境约定

- 前置:Node ≥20、Python3(标准库)、PATH 有 ffmpeg/ffprobe;浏览器矩阵需 `npx playwright install chromium`。
- 隔离:核心验证/回归均以 `MMB_DATA_DIR` 指向临时目录,自动生成管理员口令,**不触碰任何既有数据**。
- 网络:前五套中仅真实 FunASR 一套依赖外网主机(默认 10.10.10.144:8300,`FUNASR_URL` 可注入);其余全部本地 stub,离线可跑。
- 夹具:音频由脚本生成(sine wav / TTS 现场合成,仓库零音频);LLM/讯飞 stub 随套件自起,stub 行为由注入状态控制。

## 4. 测试设计原则(整改期确立,后续必须延续)

1. **运行期行为断言**:验证真实输入经真实执行路径产生结果;禁止源码字符串匹配、禁止按用例编号返回期望答案的 stub。
2. **stub 严格性**:stub 只允许依据收到的真实输入生成响应(如分块 stub 只回传 prompt 中真实出现的标记词)。
3. **先红后绿**:缺陷修复必须先提交能暴露旧缺陷的失败用例(实跑红),再修实现(绿);F01/F02 修复即按此执行(176/182 → 182/182)。
4. **故障注入必须覆盖**:空响应、坏 JSON、4xx/5xx、超限、配额边界、损坏文件;成功路径+失败路径都断言,且失败路径断言"不伪造"与"用户可见警示"。
5. **负面断言**:关键隔离类需求(分块不串块、白名单不误放、并发不越界)必须有否定断言。

## 5. 失败分类与处理口径

| 现象 | 定性 | 处理 |
|---|---|---|
| 媒体探测/ffprobe 相关失败 | 多为环境(缺 ffmpeg) | 安装后重跑;确认不是代码缺陷再升级 |
| 真实 FunASR 套件退出码 2 | 环境阻断(服务不可达/无 SAPI 语音) | 按输出提示注入 `FUNASR_WAV` 或恢复服务;**不视为用例失败,也不得宣称通过** |
| 端口占用(port busy) | 环境 | 换端口参数 |
| 其余任何断言失败 | 疑似代码缺陷 | 按《测试报告汇编》口径记录→定位→先红后绿修复 |

## 6. 变更约束

新增功能必须同步新增断言并更新本映射表;修复缺陷先写红用例;禁止删除或放宽断言来让套件通过(评审口径,违反即验收无效)。
